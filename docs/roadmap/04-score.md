# 04 · score

**Goal.** Every countable thing about the record, by domain and overall, with `n` and
refusals below minimum n. The model never computes any of these.

## Files

```
tools/lib/score-core.mjs   pure functions over an event array
tools/score.mjs            CLI: cairn score [--domain d] [--kind k] [--since date] [--summary] [--json]
tests/fixtures/*.jsonl     synthetic ledgers with a sidecar .expected.json each
tests/score.mjs            suite
```

## Statistics

All statistics are over **resolved** entries unless stated. Superseded and released
entries are excluded from Brier and calibration and counted separately. `MIN_N = 5`;
anything below reports `{ insufficient: true, n }` in place of the value.

| Name | Definition |
|---|---|
| `brier.overall` | mean of `outcome_score` over resolved scored entries (predictions, choices, commitments with a stated confidence) |
| `brier.by_domain[d]` | same, restricted to entries tagged `d` (an entry with two domains counts in both) |
| `brier.by_kind[k]` | same, by kind |
| `calibration.buckets` | after folding (confidence < 50 → `100 − c`, outcome flipped), buckets `50–59`, `60–69`, `70–79`, `80–89`, `90–100`; each: `n`, `mean_confidence`, `hit_rate`, `gap = hit_rate − mean_confidence/100` |
| `calibration.expected_error` | Σ over buckets of `(n_b / N) · |gap_b|`, only when every bucket used has n ≥ MIN_N or is omitted |
| `informativeness` | mean of `|confidence − 50| / 50` over resolved scored entries; 0 = always hedging, 1 = always certain |
| `release_rate` | released ÷ (released + resolved), over all scored kinds and notes with dates |
| `revised_count` | entries with status `superseded` |
| `overdue_count` | entries with derived status `overdue` at `now` |
| `process.mean` | mean `process_score` over resolutions; `process.by_flag` = share with adversary, criterion, reasoning |
| `stake.honored_rate` | `yes` ÷ (`yes` + `no`) over resolutions with an if-then |
| `drift` | see below |

### Drift

Reads the most recent `review` event's `priorities`: a list of `{ domain, weight }`
normalized to sum 1. Computes the share of entries **created since that review** by
domain (multi-domain entries split evenly). Reports:

- `drift.total_variation` = ½ Σ |stated_d − actual_d| in 0–1.
- `drift.by_domain[d]` = `{ stated, actual, delta }`.
- `drift.by_week[]` = actual shares per ISO week since the review, so clustering in time
  is visible.
- With no review event: `{ insufficient: true, reason: "no review recorded" }`.

## Output

`--json` prints the full object. Text mode prints a compact table per section. With
`--domain d --summary` it prints the short block the adversary receives (item 07):
Brier, calibration buckets, informativeness, overdue count, `n`, all for that domain,
each marked `insufficient` where it is.

## Fixtures

Four synthetic ledgers, generated by `tests/fixtures/generate.mjs` from a fixed seed so
they are reproducible and the expected values are derivable by hand for the small ones:

| Fixture | Construction | What it must show |
|---|---|---|
| `well-calibrated` | 60 predictions; hit rate per bucket equals bucket mean | every bucket `gap` within ±0.05; Brier ≈ mean of `c(1−c)` |
| `overconfident` | 60 predictions at 80–95 with hit rate ≈ 0.55 | `gap` strongly negative in top buckets; Brier > well-calibrated |
| `hedging` | 60 predictions at 50–58 | `informativeness` < 0.15; Brier ≈ 0.25 |
| `high-release` | 40 commitments, 18 released, 22 resolved | `release_rate` ≈ 0.45; process flags mixed |

Each fixture includes at least one `review` event with priorities so drift is
exercised, and a domain with fewer than MIN_N entries so `insufficient` is exercised.

## Tests

- Fixture values equal the sidecar expectations to three decimals.
- Folding: a 30% prediction that resolves false lands in the 70–79 bucket as a hit.
- Multi-domain entries count in each domain and split for drift.
- Superseded and released excluded from Brier; counted in their own metrics.
- Every statistic under MIN_N is `insufficient` and carries `n`.
- Drift with no review is `insufficient` with the reason.
- `--summary` output contains no field the adversary spec does not list.
